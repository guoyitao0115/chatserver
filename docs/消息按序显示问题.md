# 消息按序显示问题

## 问题结论
你说得非常有道理。

如果发送者 A 的序号是**全局递增**，那 A 发给 B 和发给 C 会共用同一序列。
这样 B 看到的来自 A 的序号就可能是 `1,3,6...`（中间被 A->C 消耗掉），接收端按“必须连续”策略会卡住，无法正确显示。

因此必须改成：
- 单聊：**每个目标接收者独立序列**
- 群聊：**每个目标群组独立序列**

---

## 最终方案（修正版）

1. 发送端移除全局 `g_clientSeq`；
2. 新增两套序列：
   - `g_peerClientSeq[toid]`（单聊按接收者）
   - `g_groupClientSeq[groupid]`（群聊按群组）
3. 发送时：
   - `chat` 使用 `nextClientSeqForPeer(friendid)`
   - `groupchat` 使用 `nextClientSeqForGroup(groupid)`
4. 接收端保持原重排逻辑：按 `client_seq` 缓冲并连续冲刷。

### 修改后的具体代码

```cpp
static mutex g_clientSeqMutex;
static unordered_map<int, uint64_t> g_peerClientSeq;
static unordered_map<int, uint64_t> g_groupClientSeq;

static uint64_t nextClientSeqForPeer(int toid)
{
    lock_guard<mutex> lock(g_clientSeqMutex);
    uint64_t &seq = g_peerClientSeq[toid];
    seq += 1;
    return seq;
}

static uint64_t nextClientSeqForGroup(int groupid)
{
    lock_guard<mutex> lock(g_clientSeqMutex);
    uint64_t &seq = g_groupClientSeq[groupid];
    seq += 1;
    return seq;
}
```

```cpp
// chat(...)
js["client_seq"] = nextClientSeqForPeer(friendid);
```

```cpp
// groupchat(...)
js["client_seq"] = nextClientSeqForGroup(groupid);
```

### 详细讲解
- 单聊序列按 `toid` 分开：A->B 与 A->C 不再互相影响。
- 群聊序列按 `groupid` 分开：A 在群 G1/G2 的序号互不干扰。
- 加 `mutex` 防止并发下序号冲突。

```cpp
static void printOrderedIncoming(const json &js)
{
    if (!js.contains("client_seq"))
    {
        cout << formatIncomingLine(js) << endl;
        return;
    }

    string key = buildSessionKey(js);
    uint64_t seq = js["client_seq"].get<uint64_t>();
    uint64_t &last = g_lastShownSeq[key];

    if (seq <= last)
    {
        return;
    }

    g_orderBuffer[key][seq] = formatIncomingLine(js);

    auto &buf = g_orderBuffer[key];
    while (!buf.empty())
    {
        auto it = buf.begin();
        if (it->first == last + 1)
        {
            cout << it->second << endl;
            last = it->first;
            buf.erase(it);
        }
        else
        {
            break;
        }
    }
}
```

### 详细讲解
- 单聊按“发送者桶”重排，群聊按“群+发送者桶”重排。
- 发送端现在已改为按目标维度独立递增，所以接收端看到的序号会连续，不会被无关会话“打洞”。

## 为什么你的建议是正确的（结论）

你提出的是“**序号作用域**”问题，本质非常专业：
- 如果序号作用域过大（发送者全局），会产生跨会话干扰；
- 正确做法是把作用域收敛到“业务展示维度”（单聊按目标用户、群聊按目标群）。

这次修改就是按这个原则完成的。
