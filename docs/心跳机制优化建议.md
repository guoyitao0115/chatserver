# 心跳机制优化建议

> 创建日期：2026-04-01
> 优化目标：将单向心跳机制改进为真正的双向心跳，提升服务端对客户端异常的检测能力

---

## 1. 当前实现分析

### 1.1 现有心跳机制

**客户端 → 服务端**：
- 客户端每 10 秒主动发送 `HEARTBEAT_MSG`
- 服务端收到后被动响应 `HEARTBEAT_MSG_ACK`
- 服务端更新 Redis 中的用户在线状态（TTL = 120秒）

**服务端 → 客户端**：
- 没有主动发送心跳
- 只是被动响应客户端的心跳请求

### 1.2 存在的问题

#### 问题1：服务端无法主动检测客户端异常
- 如果客户端挂了（进程崩溃、网络断开），服务端只能依赖：
  - TCP 层的 keepalive（通常2小时才检测）
  - Redis 在线状态过期（120秒后过期）
- 无法及时发现客户端异常，导致资源浪费

#### 问题2：缺少心跳超时检测
- 服务端没有记录每个连接最后收到心跳的时间
- 没有定时巡检机制检测心跳超时
- 无法主动断开长时间无心跳的连接

#### 问题3：不是真正的双向心跳
- 当前实现是"客户端主动检测服务端"
- 服务端只是被动响应，没有主动检测客户端
- 不符合双向心跳的标准定义

---

## 2. 改进方案

### 2.1 方案概述

实现真正的双向心跳机制：

1. **客户端 → 服务端**：保持现有机制，客户端定期发送心跳
2. **服务端 → 客户端**：新增主动心跳检测
   - 记录每个连接最后收到心跳的时间
   - 定时巡检，超过阈值未收到心跳则主动断开连接
   - 可选：服务端主动向客户端发送心跳请求

### 2.2 核心改进点

#### 改进点1：记录心跳时间
在 `ChatService` 中为每个连接记录最后收到心跳的时间

#### 改进点2：定时巡检心跳超时
在 `ChatServer` 中新增定时任务，巡检心跳超时的连接

#### 改进点3：主动断开超时连接
对超过阈值未收到心跳的连接主动断开，并清理相关状态

## 3. 具体实现

### 3.1 修改 `chatservice.hpp`

```cpp
// 在 ChatService 类中新增成员变量
class ChatService {
private:
    // 记录每个连接最后收到心跳的时间
    unordered_map<string, Timestamp> _lastHeartbeatTime;
    mutex _heartbeatMutex;

    // 心跳超时阈值（秒）
    static constexpr int HEARTBEAT_TIMEOUT_SEC = 30;

    // 心跳巡检函数
    void checkHeartbeatTimeouts();
};
```

### 3.2 修改 `chatservice.cpp`

#### 3.2.1 修改心跳处理函数

```cpp
void ChatService::heartbeat(const TcpConnectionPtr &conn, json &js, Timestamp time)
{
    // 更新该连接最后收到心跳的时间
    {
        lock_guard<mutex> lock(_heartbeatMutex);
        _lastHeartbeatTime[conn->name()] = time;
    }

    // 原有逻辑：立即响应 ACK
    json ack;
    ack["msgid"] = HEARTBEAT_MSG_ACK;
    if (js.contains("ts"))
    {
        ack["echo_ts"] = js["ts"];
    }
    if (js.contains("id"))
    {
        _redis.setUserServer(js["id"].get<int>(), _serverId, 120);
    }
    conn->send(FrameCodec::encode(ack.dump()));
}
```

#### 3.2.2 新增心跳超时巡检函数

```cpp
void ChatService::checkHeartbeatTimeouts()
{
    vector<TcpConnectionPtr> toClose;
    auto now = Timestamp::now();

    {
        lock_guard<mutex> lock(_heartbeatMutex);

        for (auto it = _lastHeartbeatTime.begin(); it != _lastHeartbeatTime.end(); )
        {
            // 计算该连接距离上次心跳已过去多久
            double elapsed = timeDifference(now, it->second);

            // 超过阈值：判定为客户端异常，准备断开
            if (elapsed >= HEARTBEAT_TIMEOUT_SEC)
            {
                // 从连接表中查找对应的连接
                TcpConnectionPtr conn = nullptr;
                {
                    lock_guard<mutex> connLock(_connMutex);
                    for (auto& [userId, userConn] : _userConnMap)
                    {
                        if (userConn->name() == it->first)
                        {
                            conn = userConn;
                            break;
                        }
                    }
                }

                if (conn)
                {
                    LOG_WARN << "[heartbeat-timeout] conn=" << it->first
                             << " timeout=" << elapsed << "s, close connection";
                    toClose.push_back(conn);
                }

                // 从心跳时间表中移除
                it = _lastHeartbeatTime.erase(it);
            }
            else
            {
                ++it;
            }
        }
    }

    // 锁外执行真正断连，避免阻塞其他线程对状态表的访问
    for (auto &conn : toClose)
    {
        conn->shutdown();
    }
}
```

#### 3.2.3 修改连接关闭处理

```cpp
void ChatService::clientCloseException(const TcpConnectionPtr &conn)
{
    // 清理心跳时间记录
    {
        lock_guard<mutex> lock(_heartbeatMutex);
        _lastHeartbeatTime.erase(conn->name());
    }

    // 原有逻辑：清理连接和用户状态
    User user;
    {
        lock_guard<mutex> lock(_connMutex);
        for (auto it = _userConnMap.begin(); it != _userConnMap.end(); ++it)
        {
            if (it->second == conn)
            {
                user.setId(it->first);
                _userConnMap.erase(it);
                break;
            }
        }
    }

    // 用户异常下线，清理在线路由并做兼容退订调用
    _redis.removeUserServer(user.getId());
    _rabbitMqBus.unsubscribe(user.getId());

    // 更新用户的状态信息
    if (user.getId() != -1)
    {
        user.setState("offline");
        _userModel.updateState(user);
        LOG_WARN << "[exception] userid=" << user.getId()
                 << " connection closed abnormally, set offline";
    }
}
```

### 3.3 修改 `chatserver.cpp`

#### 3.3.1 在构造函数中注册心跳巡检定时器

```cpp
ChatServer::ChatServer(EventLoop *loop,
                       const InetAddress &listenAddr,
                       const string &nameArg)
    : _server(loop, listenAddr, nameArg),
      _loop(loop),
      _codec(std::bind(&ChatServer::onFrameMessage, this, _1, _2, _3))

    _server.setConnectionCallback(
        std::bind(&ChatServer::onConnection, this, _1));

    // 注册消息回调
    _server.setMessageCallback(
        std::bind(&ChatServer::onMessage, this, _1, _2, _3));

    // 设置线程数量
    _server.setThreadNum(4);

    // 方案A：每秒巡检一次半包超时连接，超时则主动断开
    _loop->runEvery(1.0, std::bind(&ChatServer::checkPartialFrameTimeouts, this));

    // 新增：每秒巡检一次心跳超时连接，超时则主动断开
    _loop->runEvery(1.0, std::bind(&ChatService::checkHeartbeatTimeouts, ChatService::instance()));
}
```

## 4. 可选改进：服务端主动心跳

如果需要服务端主动向客户端发送心跳，可以进一步实现：

### 4.1 新增服务端心跳消息类型

在 `public.hpp` 中新增：
```cpp
SERVER_HEARTBEAT_MSG,      // 服务端 -> 客户端 心跳请求
SERVER_HEARTBEAT_MSG_ACK,  // 客户端 -> 服务端 心跳应答
```

### 4.2 客户端处理服务端心跳

在客户端中新增处理逻辑：
```cpp
// 接收线程中处理服务端心跳
if (SERVER_HEARTBEAT_MSG == msgtype)
{
    json ack;
    ack["msgid"] = SERVER_HEARTBEAT_MSG_ACK;
    ack["echo_ts"] = js["ts"];
    sendFrame(clientfd, ack.dump());
}
```

### 4.3 服务端定时发送心跳

```cpp
void ChatServer::sendServerHeartbeats()
{
    lock_guard<mutex> lock(_connMutex);

    for (auto& [userId, conn] : _userConnMap)
    {
        json hb;
        hb["msgid"] = SERVER_HEARTBEAT_MSG;
        hb["ts"] = chrono::duration_cast<chrono::milliseconds>(
            chrono::system_clock::now().time_since_epoch()).count();

        conn->send(FrameCodec::encode(hb.dump()));
    }
}
```

## 5. 参数配置建议

### 5.1 心跳超时阈值

- **内网高质量环境**：15-20 秒
- **公网环境**：30-45 秒
- **跨地域网络**：45-60 秒

当前建议值：`HEARTBEAT_TIMEOUT_SEC = 30`

### 5.2 巡检频率

- **当前实现**：每秒巡检一次
- **优化建议**：可根据连接数调整，如每 5 秒巡检一次

## 6. 预期效果

### 6.1 改进前
- 服务端依赖 TCP keepalive（2小时）或 Redis 过期（120秒）检测客户端异常
- 客户端异常后，服务端可能长时间无法发现
- 资源占用时间过长

### 6.2 改进后
- 服务端主动检测客户端心跳超时（30秒）
- 客户端异常后，服务端在 30 秒内主动断开连接
- 及时释放资源，提升系统整体效率
- 真正实现双向心跳机制

---

## 7. 注意事项

### 7.1 避免误判
- 心跳超时阈值要大于客户端心跳间隔（10秒）
- 考虑网络抖动，适当放宽阈值
- 可结合半包超时检测，综合判断

### 7.2 性能影响
- 巡检频率不宜过高，避免占用过多 CPU
- 使用弱引用和锁外操作，减少锁竞争
- 及时清理已关闭连接的状态记录

### 7.3 日志记录
- 记录心跳超时断连的详细信息
- 便于问题排查和性能分析
- 避免日志过于频繁影响性能

## 8. 测试建议

### 8.1 功能测试
1. 正常心跳：客户端定期发送心跳，服务端正常响应
2. 心跳超时：模拟客户端挂掉，验证服务端30秒后主动断开
3. 网络抖动：模拟网络延迟，验证不会误判

### 8.2 性能测试
1. 大量连接：测试巡检机制的性能影响
2. 高频心跳：验证系统在高频心跳下的稳定性
3. 长时间运行：测试内存泄漏和资源占用

### 8.3 边界测试
1. 阈值边界：测试正好在阈值时间点的心跳处理
2. 连接并发：测试多个连接同时超时的处理
3. 异常恢复：测试客户端恢复后的重连机制

---

## 9. 总结

当前心跳机制存在服务端无法主动检测客户端异常的问题，通过记录心跳时间、定时巡检、主动断开超时连接等改进，可以实现真正的双向心跳机制，提升系统的可靠性和资源利用效率。

建议优先实现心跳超时检测机制，根据实际需求再考虑是否需要服务端主动发送心跳。
